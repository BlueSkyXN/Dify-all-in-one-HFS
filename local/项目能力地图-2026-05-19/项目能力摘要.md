# 项目能力摘要：dify-all-in-one

## 项目目标

`dify-all-in-one` 是面向 Hugging Face Docker Space 的 Dify 单容器 Demo 工程，目标是在一个 Docker 容器和一个公开端口中承载 Dify Web、API、Worker、Beat、Plugin Daemon、Sandbox、PostgreSQL、Redis、Nginx 以及只读/受控运维入口，用于企业内训、课程演示、PoC 和快速功能验证。

主要依据：`README.md:12-16`、`docs/project-overview.md:1-12`、`Dockerfile:3-5`。

## 核心能力域

1. Hugging Face Space 单容器交付
2. Dify 核心运行时编排
3. 数据持久化与配置管理
4. 插件、Marketplace 与 Sandbox 支撑
5. 只读运维诊断与可观测
6. 受控 Admin、文件管理与终端调试
7. 本地/线上验证与工程文档
8. 发布验收与运行证据闭环

## 当前已形成能力

代码和文档已经支撑一个面向 Hugging Face Docker Space 的单容器 Dify demo：`README.md` 声明 Docker Space metadata，`Dockerfile` 复用官方 Dify Web/API、Plugin Daemon 和 Sandbox 镜像资产，并在最终镜像中安装 Nginx、Supervisor、Redis、PostgreSQL 15 + pgvector、Node.js 和 Python runtime。

运行时已经形成较完整的多进程生命周期：`entrypoint.sh` 负责目录准备、持久化布局、generated env、Redis/Sandbox 配置、PostgreSQL 初始化、pgvector、Dify migration；`supervisord.conf` 负责 Postgres、Redis、backup、Plugin Daemon、Sandbox、Dify API/Worker/Beat/Web、ops-service、admin-service、web-terminal 和 Nginx 的长期进程管理。

运维能力已经从只读 `/_ops` 扩展到默认关闭的 `/_admin`：`ops_service.py` 提供 health、status、system、config、version、logs、errors、metrics；`admin_service.py` 提供独立 `ADMIN_TOKEN`、signed cookie、CSRF、白名单 action catalog、审计日志和可选 file manager；`webssh_entrypoint.sh` 当前实现的是 disabled/缺 ttyd placeholder，不是可交互终端。

本地材料 `local/ops-admin-plan.md` 与当前代码大体对应：计划中的三层边界是 `/healthz` public health、`/_ops` 只读诊断、`/_admin` 受控管理，代码层已经看到 admin service、file manager、terminal placeholder、Nginx route 和 smoke 脚本入口。

结合 `git log` 看，项目演进从 5 月 17 日的官方 Dify 资产/Sandbox/Redis/migration 适配，推进到 5 月 18 日的 ops diagnostics 和文档体系，再到 5 月 19 日的 bucket fallback、iframe、admin control plane 和 HF config defaults。这个提交脉络显示后续能力不应只看“已经写了哪些代码”，还要补发布验收闭环、bucket 演练、Admin/File 场景验证、ops 后续增强和文档默认值一致性。

本轮按新版 `project-research` 边界重做能力地图，未把旧的 `local/research-2026-05-19/` 深度研究包作为事实来源。

## 当前主要缺口

- 缺少本轮 Docker build、local run、HF Space live smoke 的实测证据；多数 runtime endpoint 只能标为 `已开发` 或 `待验证`，不能写成已经线上验证。
- 文档存在少量事实漂移风险：例如 `README.md`、`docker/dify.env.runtime` 和 `docs/configuration.md` 显示 `MARKETPLACE_ENABLED=true`，但 `docs/project-overview.md` 仍写 Marketplace 默认关闭。
- `/_admin/terminal/` 当前只有 placeholder 证据，镜像未安装 `ttyd`，因此不能视为已经具备真实交互式 Web terminal。
- `local/ops-admin-plan.md` 中的验证设想已经有脚本和代码承接，但默认 admin-disabled、admin-enabled、file manager 和线上 Space 路径仍需要分场景 smoke。
- 基于 `docs/ops-runbook.md` 的后续可扩展方向，`/_ops` 还可以继续补日志筛选、build/runtime SHA 漂移提示、Plugin Daemon schema 只读检查和 warmup 状态区分；这些已在能力表中标为 `已规划`。
- 基于近期 git 提交集中区，后续回归应覆盖 Sandbox、bucket persistence、ops diagnostics、admin control plane、HF config defaults 和 iframe header。

## 可用于汇报的一句话

本项目已经把 Dify 的核心演示运行时、持久化、插件/Sandbox、只读诊断和默认关闭的受控管理面收敛进 Hugging Face Docker Space 单容器形态；结合 git 历史和 local 计划，下一步重点是补齐发布验收证据闭环、bucket 演练、Admin/File 场景验证、ops 增强和文档默认值一致性。
